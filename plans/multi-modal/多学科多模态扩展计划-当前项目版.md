# 多学科多模态扩展计划（当前项目版）

## 1. 当前项目状态

本项目已经不是完全的纯文本系统。L1 公式支持已经有部分实现：

- 出题规划已有 LaTeX 公式规范：`exam/agents/planner/chief_editor.py`
- 前端已有 KaTeX 渲染函数：`web/js/all.js`
- 判题已有 LaTeX 包裹符和空白归一化：`exam/graph/judge_graph.py`
- 学生画像已区分纯文本标题和富文本标题：`exam/student_profile/profile_presenter.py`

因此后续计划应以“L1 收口 + L2/L3/L4 扩展”为主，而不是从纯文本系统重新起步。

## 2. 核心原则

1. LaTeX 是文本富渲染能力，不放进 `media`
2. `media` 只承载非文本资产：图片、Mermaid、Canvas
3. `media` 使用数组，支持一题多图或多媒体组合
4. 图片描述写入 `sections.text` 参与检索，图片资产另建 manifest 管理
5. Canvas 优先作为结构化题图展示，交互作答暂缓到专项阶段
6. 所有新增结构必须兼容旧版 `questions_*.json`

## 3. 推荐题目结构

```json
{
  "question_type": "choice",
  "stem": "根据 [media:fig1] 回答问题。",
  "options": ["A. ...", "B. ...", "C. ...", "D. ..."],
  "correct_answer": "A",
  "explanation": "...",
  "media": [
    {
      "id": "fig1",
      "type": "image",
      "src": "cache/books/book1/images/a3f2b1c0.png",
      "sha256": "...",
      "description": "该图展示了任务状态转换过程。"
    }
  ]
}
```

没有图像、图表、交互内容的题目可以不带 `media` 字段，旧数据继续可用。

## 4. 阶段规划

### 阶段 0：L1 公式支持收口

目标：把已经存在的公式能力稳定下来。

工作内容：

- 检查所有前端渲染点是否都经过 `esc()` 后再 `renderLatex()`
- 修正选择题选项中可能直接插入 HTML 的位置
- 质检 prompt 增加公式格式检查
- 离线评测补充 LaTeX 样例

结论：

`media.type = "latex"` 不需要。公式直接保留在 `stem`、`options`、`explanation`、`correct_answer` 等文本字段里。

### 阶段 1：media 协议落地

目标：先建立扩展边界，避免 L2/L3/L4 各自加字段。

工作内容：

- 题目 schema 允许可选 `media: list[dict]`
- 生成器默认不输出 `media` 或输出空数组
- 前端增加 `renderMediaList(q.media)`
- 判题接口透传 `media`
- 离线评测兼容有无 `media` 的题目

### 阶段 2：L2 静态图入库

目标：教材图片可被检索、引用、展示。

工作内容：

- PDF 解析阶段提取图片
- 图片按 SHA256 命名
- 每本书独立资产目录：`cache/books/{book_id}/images/`
- 建立图片 manifest，记录图片元信息
- 多模态模型生成图片描述
- 图片描述写入 `sections.text`

示例：

```text
[插图: fig1]
该图展示了 μC/OS-II 中任务从等待态、就绪态到运行态之间的转换关系。
```

### 阶段 3：L2 静态图出题与展示

目标：题目可以引用教材图片。

工作内容：

- 出题 agent 能识别 `[插图: fig1]`
- 生成题目时写入 `media`
- 前端支持 `type=image`
- 判题 prompt 附加图片 description
- 暂不做视觉判题，仍走文字描述判题

### 阶段 4：L3 Mermaid 生成图

目标：支持结构图、流程图、状态转换图。

工作内容：

- 新增 `media.type = "mermaid"`
- 限制 Mermaid 子集
- 前端引入 Mermaid renderer
- 生成器 prompt 要求输出合法 Mermaid
- 评测增加 Mermaid 基础合法性检查

支持子集：

```text
flowchart
graph TD
sequenceDiagram
gantt
```

### 阶段 5：生成质量门禁与回归用例

目标：把多模态输出纳入离线评测，避免回归。

工作内容：

- 增加关键词命中率检查
- 增加 LaTeX 公式格式检查
- 增加 `media` 契约检查
- 增加 Mermaid 基础合法性检查
- 增加期望媒体类型检查
- 补充 LaTeX、图片、Mermaid、Canvas 静态回归样例

### 阶段 6：L4 Canvas 结构图协议

目标：先定义 Canvas 结构图协议，不急着实现复杂交互编辑。

建议结构：

```json
{
  "id": "canvas1",
  "type": "canvas",
  "config": {
    "canvas_type": "tree",
    "initial_state": {},
    "tools": ["add_node", "draw_edge"]
  },
  "expected_answer": {},
  "judge_schema": {
    "mode": "structural_diff",
    "ignore_fields": ["x", "y"],
    "partial_credit": true
  }
}
```

注意：

后端判题入口可以统一，但 evaluator 需要允许按题型扩展。树结构、电路、几何不会永远只靠 JSON 相等判断。

当前实施口径：

- 已落地 `media.type = "canvas"` 协议字段
- 已支持前端只读结构预览
- 已接入质检、判题上下文和离线评测基础契约
- 暂不支持学生直接拖拽、连线或编辑画布作答

### 阶段 7：图文题生成质量增强

目标：把系统稳定在“看图作答，不操作图”的考试形态上。

工作内容：

- 生成器明确要求 media 只作为题图或结构预览
- 图文题题干必须出现 `[media:id]` 并表达“根据图/结合图/观察图中信息”
- 质检拒绝点击、拖拽、连线、编辑画布、在图上标注等交互作答要求
- 离线评测增加图文题引用、只读作答、媒体描述质量门禁
- 前端增加图片大图查看，降低看图题阅读成本

### 阶段 8：图片描述生成与教材图语义补全

目标：让教材图片不再停留在“可显示”，而是拥有可检索、可出题、可判题参考的文字描述。

工作内容：

- PDF 解析阶段基于章节标题、页码、相邻文本生成保守图片描述
- `media_manifest.json` 写入 `description`、`description_source`、`context`、章节信息
- `sections.text` 中的 `[插图: figX]` 块写入同一份媒体描述，参与检索和出题
- 新增手动补全脚本，用于给已有教材 manifest/sections 回填描述
- 生成器跳过描述缺失或占位的图片，避免围绕语义不清的图出题

限制：

当前描述来自文本上下文推断，不是真正的视觉模型识图；后续如接入视觉模型，可在同一 manifest 字段上升级描述质量。

## 5. 推荐执行顺序

1. L1 收口
2. `media: []` 协议落地
3. 图片资产 manifest
4. 静态图展示
5. 静态图出题
6. Mermaid 生成图
7. 生成质量门禁与回归用例
8. L4 Canvas 结构图协议
9. 图文题生成质量增强
10. 图片描述生成与教材图语义补全
11. 完整交互编辑器专项（暂缓）

## 6. 需要修正的原计划口径

- 删除 `media.type = "latex"`
- `media` 从对象改成数组
- L1 从“下一步实现”改成“已初步实现，待收口”
- L2 增加图片 manifest，不只依赖 content-hash 文件名
- L4 改为“统一判题入口 + 可扩展 evaluator”，不要承诺后端永远不变

## 7. 总结

这条路线应该从“富文本稳定化”开始，而不是急着进入图形引擎。

最优路径是：

```text
LaTeX 收口
-> media 协议
-> 图片资产管理
-> 静态图展示和出题
-> Mermaid
-> Canvas 结构图预览
-> 图文题质量增强
-> 图片语义描述补全
```

这样可以最大限度复用现有文本管道，同时给多学科、多模态题型留下干净的扩展空间。
